# ai-news — User Interface Implementation Plan (Plan 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reader for the two verticals the backend already fills — day sections of ranked
cards, a nav between AI and Design, and a story page that shows why each item ranked where it did.

**Architecture:** Next.js App Router on Vercel. Every read is a **server component** talking
straight to DynamoDB with the read-only `VercelReader` credentials; nothing reaches the browser
but rendered HTML. One `Query` serves a whole day for both verticals, so the nav is a
client-side filter over already-fetched data. `/api/ingest` is a trigger only.

**Tech Stack:** Next.js 16.3, React 19.2, Tailwind 4.3, TypeScript 5.9 (ESM), `@aws-sdk/lib-dynamodb`
3.1112, Vitest 4.1. Node 24 locally.

**Spec:** `docs/superpowers/specs/2026-08-18-ai-news-design.md` — §7 is the binding UI section,
and §4's access patterns bound what a page may read. Where this plan and the spec disagree, the
spec wins and the conflict is a finding to report.

**Depends on:** Plans 1 and 2, merged and **deployed**. The table is live and filling hourly;
`queryDay`, `listDays`, `dayHasArticles` and `getLatestCompleteDay` already exist in
`src/lib/store/query.ts` and are tested. Do not reimplement them.

## Global Constraints

Every task's requirements implicitly include this section. Most of these are not style rules —
each one is a defect this project already found and closed.

- **`summary` renders as TEXT. Never `dangerouslySetInnerHTML`.** Tag stripping at ingest is a
  heuristic that deliberately errs toward keeping text, so a summary can legitimately contain
  `<model>`, `<think>` or bare `<`. It is written to an archive that cannot be re-fetched, which
  is why ingest keeps it; the UI's job is to render it inertly.
- **Never compute a date to decide what to show.** Follow `META#DAY`. Readers that derive "today"
  disagree with the writer across the 21:00 UTC boundary, every single day.
- **A `scoreVersion` of `v1-degraded` means the model never scored that article.** Spec §2
  requires it be marked "new since last ranking" rather than mixed silently into a ranking it
  was not part of.
- **A `clusterId` beginning `__self__:` is not a cluster.** Show no "also covered by" affordance
  for it; its `corroborationToday` is 1 by construction.
- **`getLatestCompleteDay` may return a `partial` day.** It falls back to the newest day of any
  status, because preferring "complete" without a fallback makes an unlucky run of days show
  the reader nothing. Read `status`, `llmRanked` and `truncated` and say so in the UI.
- **The per-day count is per vertical.** `META#DAY.articleCount` is the total across both
  sections; a filtered feed must count the filtered list.
- **The `/api/ingest` secret must never reach the browser bundle.** No `NEXT_PUBLIC_` prefix, no
  import from a client component. Compare with `timingSafeEqual`, never `===`.
- **`VercelReader` cannot write.** Spec §9's per-day run counter for `/api/ingest` therefore
  cannot live in this layer; it belongs to the capture Lambda. Do not add a write path here.
- ESM, `"type": "module"`. Source files import each other with a `.js` extension though the files
  on disk are `.ts`.
- No secret, no account id and no table name hardcoded — all from environment variables.
- Never add "Generated with Claude Code" / "Co-Authored-By: Claude" to anything, including commit
  messages. Hard rule.
- Never merge, never push to a shared branch.

where the tests go. The components stay thin enough to read in one screen.

### Task 2: `shape.ts` — every decision that is easy to get wrong, in one pure file

The components stay thin because this file holds the rules. All of these come from defects this
project already found; none is a preference.

**Files:**
- Create: `src/lib/feed/shape.ts`
- Test: `tests/feed/shape.test.ts`

**Produces:**
- `type FeedArticle` — a card's worth of data, derived from a raw DynamoDB item
- `toFeedArticle(item): FeedArticle`
- `bySection(articles, section): FeedArticle[]`
- `clusterSiblings(articles, article): FeedArticle[]`
- `isUnranked(article): boolean`

- [ ] **Step 1: Write the failing tests**

```ts
import { describe, expect, it } from "vitest";
import { bySection, clusterSiblings, isUnranked, toFeedArticle } from "../../src/lib/feed/shape.js";

const raw = (over: Record<string, unknown> = {}) => ({
  pk: `ART#${"a".repeat(64)}`, sk: "A",
  title: "T", summary: "s", imageUrl: null, url: "https://e.com/p",
  source: "techcrunch", sourceName: "TechCrunch", category: "news", section: "ai",
  publishedAt: "2026-08-18T09:00:00.000Z", clusterId: "2026-08-18#gpt6",
  corroborationToday: 2, whyItMatters: "Because.", score: 812, scoreVersion: "v1",
  points: null, pointsImputed: true, llmImportance: 88, firstSeenAt: "2026-08-18T10:00:00.000Z",
  ...over,
});

describe("toFeedArticle", () => {
  it("recovers urlHash from the key rather than expecting an attribute", () => {
    // urlHash is not a projected attribute. It is recoverable from `pk`, which DynamoDB
    // projects into every index regardless of projection type.
    expect(toFeedArticle(raw()).urlHash).toBe("a".repeat(64));
  });

  it("survives an item missing every optional attribute", () => {
    // A degraded day has no whyItMatters, no llmImportance and no clusterId. Most sources
    // never carry points or an image. A card that needs them is a card that breaks daily.
    const a = toFeedArticle(raw({ whyItMatters: undefined, llmImportance: undefined,
      clusterId: undefined, imageUrl: undefined, points: undefined }));
    expect(a.whyItMatters).toBeNull();
    expect(a.imageUrl).toBeNull();
    expect(a.title).toBe("T");
  });
});

describe("isUnranked", () => {
  it("is true exactly when the model never scored the article", () => {
    expect(isUnranked(toFeedArticle(raw({ scoreVersion: "v1-degraded" })))).toBe(true);
    expect(isUnranked(toFeedArticle(raw({ scoreVersion: "v1" })))).toBe(false);
  });
});

describe("bySection", () => {
  it("filters to one vertical and preserves the ranked order", () => {
    const items = [raw({ score: 900 }), raw({ section: "design", score: 800 }), raw({ score: 700 })]
      .map(toFeedArticle);
    const ai = bySection(items, "ai");
    expect(ai).toHaveLength(2);
    expect(ai.map((a) => a.score)).toEqual([900, 700]);
  });
});

describe("clusterSiblings", () => {
  it("finds the other articles covering the same story", () => {
    const items = [raw({ title: "A" }), raw({ title: "B" }),
      raw({ title: "C", clusterId: "2026-08-18#other" })].map(toFeedArticle);
    expect(clusterSiblings(items, items[0]!).map((a) => a.title)).toEqual(["B"]);
  });

  it("returns nothing for a __self__ id, which is not a cluster", () => {
    // reconcile assigns `__self__:<hash>` when the model gave no cluster. Treating it as one
    // would group every unclustered article of the day into a single fake story.
    const items = [raw({ clusterId: "__self__:h1" }), raw({ clusterId: "__self__:h2" })]
      .map(toFeedArticle);
    expect(clusterSiblings(items, items[0]!)).toHaveLength(0);
  });

  it("never returns the article itself", () => {
    const items = [raw()].map(toFeedArticle);
    expect(clusterSiblings(items, items[0]!)).toHaveLength(0);
  });
});
```

- [ ] **Step 2: Run them, watch them fail, then write `shape.ts`**

Keep it pure — no React, no AWS SDK, no `Date.now()`. Everything it needs arrives as an argument.
That is what lets these rules be tested without a browser or a network.


### Task 3: `read.ts` — the server-only data layer

**Files:** Create `src/lib/feed/read.ts`; Test `tests/feed/read.test.ts`

**Produces:** `getFeed(section)`, `getDay(date)`, `getArticle(urlHash)`, `getArchive(limit)`,
`getRunStatus()`

- [ ] **Step 1: `import "server-only"` at the top of the file, before anything else.**

That import is not decoration. It makes the build fail if a client component ever imports this
module — which is the only mechanism that stops AWS credentials being pulled toward the browser
bundle by an innocent-looking refactor. `pnpm add server-only`.

- [ ] **Step 2: Reuse the store layer; do not reimplement it**

`queryDay`, `listDays`, `dayHasArticles` and `getLatestCompleteDay` already exist in
`src/lib/store/query.ts`, are tested, and page their results to exhaustion. `read.ts` wraps them
and maps raw items through `toFeedArticle`. It adds no new query shapes.

`getArticle(urlHash)` is the one genuinely new read: a `GetItem` on `ART#<urlHash>` / `A`, which
returns the **full** item rather than the 18 projected attributes — that is where the detail page
gets `points`, `publishedAtSource` and the rest.

- [ ] **Step 3: The feed's entry point follows the pointer**

`getFeed` calls `getLatestCompleteDay`, then queries that day. It must **not** compute a date.
Remember the fallback: that function returns the newest day of *any* status when no complete day
exists in the last 30, so `getFeed` returns the day's `status`, `llmRanked` and `truncated`
alongside the articles and the UI says what it is looking at.

- [ ] **Step 4: Tests with `aws-sdk-client-mock`, no network**

Assert: `getFeed` reads the day the pointer names and not a computed one; a `partial` day is
returned rather than swallowed; `getArticle` reads the base table, not the index; a missing
article returns null rather than throwing.

### Task 4: `ArticleCard` and `DaySection`

**Files:** Create `components/ArticleCard.tsx`, `components/DaySection.tsx`;
Test `tests/feed/card.test.tsx`

- [ ] **Step 1: Design the imageless, rationale-less card FIRST**

Spec §7 is explicit and the live data agrees: `imageUrl` is absent on a large share of items —
HN, research papers, several RSS feeds — and `whyItMatters` is absent on every article of a
degraded day. **The bare card is the layout; the decorated one is the enhancement.** Build it in
that order or the common case will look broken.

A card shows: title, `sourceName`, relative published time, the summary (**as text**), and when
present `whyItMatters` and the image. When `corroborationToday > 1` and the cluster is real, a
quiet "also covered by N others". When `isUnranked`, the "new since last ranking" marker.

- [ ] **Step 2: The whole card is one link to `/article/[urlHash]`**

Not to the source. Spec §7: the detail page is what the app adds; the outbound link lives there.

- [ ] **Step 3: `DaySection`**

A header with the date and **the count of the articles it is actually showing** — not
`META#DAY.articleCount`, which totals both verticals. Then the cards, already in score order
from the query.

- [ ] **Step 4: Tests**

Render with: no image; no `whyItMatters`; a `__self__:` cluster (no "also covered by"); a
`v1-degraded` article (marker present); a summary containing `<model>` and `<script>alert(1)</script>`
(**both must appear as visible text, and no script tag may exist in the DOM**). That last one is
the test that matters most: it is the standing defence for the ingest heuristic that deliberately
keeps bracketed prose.

### Task 6: The story page

**Files:** Create `app/article/[urlHash]/page.tsx`, `components/ScoreSignals.tsx`

- [ ] **Step 1: What the page is, and is not**

Spec §7: **we never fetch article bodies.** This is a story page, not a reader view. It shows
what we know and then sends the reader onward: title, hero image, source, published time, our
summary, `whyItMatters` given prominence — it is the thing the app adds — the score's signals,
the cluster siblings, and a prominent link to the original.

- [ ] **Step 2: `ScoreSignals` — make the ranking inspectable**

Source weight (from `category`), corroboration today, engagement where it exists. **When
`pointsImputed` is true the engagement figure was imputed at a neutral 0.5, not measured** —
show it as such or the page presents a guess as a measurement, which is the dishonesty spec §5
corrected when it renamed `clusterSize` to `corroborationToday`.

- [ ] **Step 3: Cluster siblings** — "also covered by …", each linking to its own story page.
Nothing for a `__self__:` id.

- [ ] **Step 4: A missing hash is a 404, not a crash.** `notFound()`.

- [ ] **Step 5: Tests + commit**

### Task 8: Search

**Files:** Create `app/search/page.tsx`

- [ ] **Step 1: Read spec §8's search section before writing anything.** It sets the mechanism
and the reason: **last 30 days** comes from GSI1, one Query per day partition; **older** comes
from the NDJSON exports on GitHub, one HTTP GET per month, filtered in memory, zero DynamoDB
reads.
- [ ] **Step 2:** Do not "improve" this into a range query. A DynamoDB Query needs one exact
partition key, so a year-long search would be 365 queries and ~6,800 RCU — and a `FilterExpression`
would not help, because filters are applied *after* the read and cost the same capacity. The
backup artifact doubles as the deep-search index; that is why it exists in that format.
- [ ] **Step 3:** Search within the current vertical by default, with a way to search both.
- [ ] **Step 4:** Tests for the query-splitting logic (pure, no network) + commit

### Task 9: The header status line, and `/api/ingest`

**Files:** Create `components/RunStatus.tsx`, `app/api/ingest/route.ts`; modify `app/layout.tsx`

- [ ] **Step 1: `RunStatus` — the highest-value thing on the page**

Spec §8: reads `META#lastRun` and renders `last run 4h ago · 229 items · 21/21 sources · LLM ok`.
Without it, a feed that has been quietly broken for a week is indistinguishable from a quiet news
week — the failure this whole system is most likely to have.

Use the five states spec §8 defines, and only the last two may show red:

| produced | filtered | quarantined | error | state | shown as |
|---|---|---|---|---|---|
| >0 | any | 0 | no | healthy | normal |
| 0 | >0 | 0 | no | quiet — nothing recent enough | grey |
| any | any | >0 | no | **parser or schema drift** | amber, never hidden |
| 0 | 0 | 0 | yes | fetch failed | amber; red after two runs |
| 0 | 0 | 0 | no | **dead — nothing at all** | red after two runs |

`alistapart` is reliably in row 2 and `anthropic` reliably in row 3 (one degenerate title a day).
Those are not faults, and a UI that shows them as faults trains the reader to ignore the line.

- [ ] **Step 2: `/api/ingest` — a trigger, and nothing else**

`POST` only. Compare the secret header with `timingSafeEqual` (never `===`; `===` leaks length
and position through timing). Then `lambda:InvokeAsync` on the capture function and return 202.

It must **not** call Bedrock, and must not be able to: spec §2 exists because a refresh path that
reaches ranking lets a stuck finger, or a leaked secret, spend the credit balance. The
`VercelReader` credentials have no Bedrock permission at all, so this holds structurally — keep it
that way.

- [ ] **Step 3: The secret never reaches the browser**

No `NEXT_PUBLIC_` prefix. No import of this route's module from a client component. If the UI
grows a "refresh now" button it calls a Server Action holding the secret server-side — spec §9.

- [ ] **Step 4: The run counter is NOT here.** Spec §9 asks for a per-day counter so a leaked
secret caps out. `VercelReader` has no write permission by design, so it cannot live in this
layer; it belongs to the capture Lambda. Note it in the report rather than adding a write path.

- [ ] **Step 5: Tests** — wrong secret → 401 and no invoke; `GET` → 405; correct secret → 202 and
exactly one invoke. Assert `timingSafeEqual` is what compares, by mutation.

- [ ] **Step 6: Commit**

`TABLE_NAME`, `AWS_REGION`, `CAPTURE_FUNCTION_NAME`, `INGEST_SECRET`, plus the `VercelReader`

- [ ] **Step 2: Mint the access key — human only**

⚠️ **The key is invisible to `cdk diff`.** Anything that forces replacement of the `VercelReader`
construct destroys it silently and the site starts erroring with no deployment warning.

- [ ] **Step 3: Verify the deployed site reads real data**

The home feed shows the day `META#DAY` points at, with per-vertical counts that match what the
smoke script reports. If they disagree, the UI is computing a date somewhere.

- [ ] **Step 4: Confirm the secret is not in the bundle**

Search the built client output for the secret's value and for `INGEST_SECRET`. Neither may appear.
This is a grep, it takes ten seconds, and it is the difference between a private trigger and a
public one.

## Out of scope

- Fetching or storing article bodies — spec §11, different product, different legal footing.
- Accounts, personalisation, saved articles. One reader, no auth.
- Writing anything to DynamoDB from this layer. `VercelReader` is read-only by design.
- Changing the ranking, the sources or the schedules. That is Plan 2's territory and it is live.
